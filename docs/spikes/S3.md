# S3 findings: KWin script placement via events

Date: 2026-10-17. KWin 6.7.5 (nested `kwin_wayland --virtual`, 1920x1080,
Xwayland on), Qt 6.12, KF6 6.31. Everything below ran in a private nested
session (`VDW_DEV_DIR=/run/user/1000/vdw-s3 scripts/dev-session.sh ...`);
nothing touched the live session.

## Summary

| Question | Answer | Verified |
|---|---|---|
| 1. Load/unload at runtime, get work into a loaded script | `loadScript(path, name)` + `/Scripting/ScriptN run`, `unloadScript(name)` all work. Best way to get work in: the script **pulls** it with `callDBus` (with a reply callback) when it needs it. | yes |
| 2. App id set on `windowAdded`? `frameGeometry` sticks? | Yes: `desktopFileName` and `resourceClass` are already set (Konsole, Kate, Dolphin, Konsole on Xwayland). Setting `frameGeometry` in the handler, or 1 to 5 ms later in a `callDBus` reply, sticks; no app resized itself afterwards (checked at +50/250/1000/3000 ms). | yes |
| 3. Report back with `callDBus` | Works, both fire-and-forget and with a reply callback (reply value arrives as a JS string). | yes |
| 4. List current-desktop windows with geometry and app id | Works (`workspace.stackingOrder` filtered by desktop), including minimized windows and fractions of the usable area. | yes |
| 5. Port emptiness check and usable area | Both ported. The legacy `normalWindow` filter is **not enough** on 6.7: a plain layer-shell surface counts as a normal window on all desktops. Use `normalWindow && minimizable`. `clientArea(PlacementArea, ...)` subtracts layer-shell exclusive zones. | yes (with a fake panel, not plasmashell) |

## Setup

Throwaway code in `spikes/S3/`:

- `receiver.py`: stand-in for vdwd on the nested bus (PyGObject / Gio;
  `dbus-next` and `jeepney` are not installed, `gi` and `dbus-python` are).
  Owns `org.kde.vdw.S3`, object `/S3`, interface `org.kde.vdw.S3` with
  `Log(s)`, `Report(s)`, `ClaimWindow(s) -> s`, `TakeWork() -> s`, and driver
  methods `AddPending(s,i,i,i,i)`, `QueueWork(s)`, `Pending() -> s`. Logs with
  a monotonic timestamp.
- `placer.js`: the long-lived event-driven script (placement, check, area,
  list, doorbell).
- `oneshot-query.js`: the "one small script per request" alternative.
- `probe.js`, `window-types.js`, `readconfig.js`, `close-app.js`,
  `setup-desktops.js`: probes and test fixtures.
- `fakepanel/`: 30-line Qt + LayerShellQt client: a 44 px bottom
  layer-shell surface with an exclusive zone, because the nested session has
  no plasmashell. Built out of tree with `cmake -G "Unix Makefiles"`.
- `q.sh`: driver helpers (`load`, `unload`, `loaded`, `poke`, `pending`,
  `work`, `launch`, `log`), all going through `scripts/dev-session.sh run`.

Typical run:

```
VDW_DEV_DIR=/run/user/1000/vdw-s3 scripts/dev-session.sh start
VDW_DEV_DIR=/run/user/1000/vdw-s3 setsid -f scripts/dev-session.sh run -- \

spikes/S3/q.sh log
```

## 1. Loading, unloading, getting work in

### Load / unload

```
loadScript(/abs/path/placer.js, vdw-s3-placer)   -> 0
/Scripting/Script0 org.kde.kwin.Script.run
isScriptLoaded(vdw-s3-placer)                    -> true
loadScript(... same name again ...)              -> -1   (and no Script-1 object)
unloadScript(vdw-s3-placer)                      -> true
isScriptLoaded(vdw-s3-placer)                    -> false
unloadScript(vdw-s3-placer)                      -> false
```

- Script ids are reused after unload (a later load got id 0 again), so
  always use the id returned by the load you just did.
- Loading a name that is still loaded returns -1. A daemon that crashed and
  restarts will hit this, so startup must be: `isScriptLoaded(name)` ->
  `unloadScript(name)` -> `loadScript` -> `run`.
- After `unloadScript`, the script's signal handlers are gone (a Konsole
  launched afterwards produced no `ADDED` line).
- The time to load, run and get a `callDBus` report back from a trivial
  script is under the ~12 ms it takes to start one `qdbus6` process: three
  rounds of `Log marker; load+run; Log marker` gave the report 24 to 26 ms
  after the first marker, with two `qdbus6` process starts in between.

### Options for passing work to a loaded script

| Option | Result |
|---|---|
| **Script pulls with `callDBus` + callback** (e.g. `ClaimWindow` on `windowAdded`) | Works. Round trip 1 to 5 ms (the 10 ms outlier was the first call). Needs no push channel at all for placements. **Recommended.** |
| **One-shot script per request** (`oneshot-query.js`: load, run, it reports via `callDBus`, unload) | Works, a few ms on the KWin side. Fine for check / area / list, which are rare and user-triggered. **Recommended for queries.** |
| **Doorbell**: script calls `registerShortcut("VDW S3 Poke", ..., "", fetchWork)`; daemon calls `org.kde.kglobalaccel /component/kwin invokeShortcut "VDW S3 Poke"`; script then pulls with `TakeWork` | Works (`TAKEWORK` 12 ms after the `QueueWork`, i.e. one `qdbus6` start). But the action is **persisted** in `kglobalshortcutsrc` (`VDW S3 Poke=none,none,VDW S3: fetch work from daemon`) under the KWin component, shows up in System Settings, Shortcuts, and stays registered after `unloadScript` (invoking it then is a silent no-op). Not recommended. |
| Script config (`readConfig`) | Did not work as tried: wrote `[Script-vdw-s3-cfg] work=hello1` into the nested `kwinrc` with `kwriteconfig6`, loaded the script as `vdw-s3-cfg`, `readConfig("work", "none")` returned `none`, also after `org.kde.KWin.reconfigure`. Not pursued further: it would mean writing the user's `kwinrc` and has no change notification anyway. |
| Prefetch (push pending placements into the script's memory via the doorbell, apply synchronously in `windowAdded`) | Works (`PLACE(sync)` for Kate and Dolphin) but gave no visible benefit over the async pull, and needs the doorbell. |

KWin scripts cannot export D-Bus methods, and there is no `setTimeout`, but
`new QTimer()` works (`singleShot`, `interval`, `timeout.connect`, `start`),
so a script can poll if it ever has to.

## 2. `windowAdded`: app id and geometry

Observed `ADDED` lines (abridged; captions elided):

```
konsole (Wayland):  desktopFileName=org.kde.konsole resourceClass=org.kde.konsole resourceName=konsole
                    pid=131513 normalWindow=true desktops=[Desktop 1] frameGeometry=504,292 911x496
dolphin (Wayland):  desktopFileName=org.kde.dolphin resourceClass=org.kde.dolphin pid=132037 580,251 760x578
kate (Wayland):     desktopFileName=org.kde.kate    resourceClass=org.kde.kate    pid=132028 640,286 640x508
konsole (Xwayland, QT_QPA_PLATFORM=xcb):
                    desktopFileName=org.kde.konsole resourceClass=konsole        pid=136095 650,270 700x540
fakepanel (layer-shell): desktopFileName="" resourceClass=fakepanel normalWindow=true onAllDesktops=true
```

- App ids are present at `windowAdded`; no `desktopFileNameChanged` or
  `windowClassChanged` fired later for any of them.
- On X11 (Xwayland) `resourceClass` is the WM_CLASS (`konsole`), not the
  desktop id. Match on `desktopFileName` first; `resourceClass` only as a
  fallback (S4).
- `pid` is set. Each `konsole`/`dolphin` launch here was its own process;
  single-process reuse is S4's topic.
- The first `frameGeometry` reported is KWin's own initial placement (or the
  size the app restored from its state file: Konsole came back at 960x540
  and 800x400 after earlier runs saved those sizes).

Placement result (async path, three Konsoles launched at once, slots like
`setup-workspace.sh`):

```
106.203 CLAIM {27882de1..} -> {"x": 960, "y": 0, "width": 960, "height": 540} (pending for 141 ms)
106.203 CLAIM {060a21b8..} -> {"x": 0, "y": 540, "width": 700, "height": 540} (pending for 129 ms)
106.205 GEOM  {27882de1..} 960,0 960x540
106.206 PLACE(async rtt=3ms) {060a21b8..} before=520,293 960x540 asked=0,540 700x540 now=520,293 960x540
106.206 CLAIM {0d196af3..} -> {"x": 960, "y": 540, "width": 960, "height": 540} (pending for 119 ms)
106.211 GEOM  {060a21b8..} 0,540 700x540
106.257 CHECK +50ms   ... all three OK
109.355 CHECK +3000ms ... all three OK
```

Findings:

- Setting `w.frameGeometry = {x, y, width, height}` (a plain JS object is
  accepted) sticks for Konsole, Kate, Dolphin and Xwayland Konsole. No app
  resized itself afterwards; no re-apply was needed in any run.
- **Reading `frameGeometry` right after the assignment is not reliable on
  Wayland.** A pure move reads back at once; a resize reads back the old
  rect until the client acks the configure, then `frameGeometryChanged`
  fires with the final rect 5 to 10 ms later. On Xwayland the new rect reads
  back immediately. Confirm placement on `frameGeometryChanged` (or a short
  timer), not on the read-back.
- Windows were claimed in the order they mapped, not the order they were
  launched (pids came back 132955, 132946, 132937 for launches in the
  opposite order). For identical apps that does not matter.
- `w.desktops = [desktop]` works from a script (used in `setup-desktops.js`
  to move Kate to a second desktop), so the script can also pin a new window
  to the target desktop.

### Timing

- Launch to `windowAdded`: 113 to 215 ms (Konsole 113 to 141 ms, Kate and
  Dolphin about 150 ms, Xwayland Konsole 203 ms), measured from the
  receiver's `AddPending` (done just before the launch) to `CLAIM`. Caches
  were warm (the live session uses the same binaries); a cold first launch
  after login will be slower.
- `windowAdded` to `ClaimWindow` reply: 1 to 5 ms (one 10 ms outlier).
- `windowAdded` to final geometry (`GEOM`): 2 to 10 ms.

## 3. Reporting back with `callDBus`

```js
callDBus("org.kde.vdw.S3", "/S3", "org.kde.vdw.S3", "Log", "hello from probe");    // fire and forget
callDBus("org.kde.vdw.S3", "/S3", "org.kde.vdw.S3", "TakeWork",
         function(r) { print(typeof r + " " + r); });                              // "string []"
```

- Arguments are converted from JS (strings, ints worked); returning one `s`
  and passing JSON is simplest and avoids type-mapping questions.
- If the service is not on the bus, the callback is **never called**; KWin
  only logs `Received D-Bus message is error: "The name org.kde.vdw.S3 was
  not provided by any .service files"`. So the script must never wait for a
  reply to make progress, and a D-Bus `.service` file for vdwd would make
  `callDBus` auto-start it.

## 4. Listing current-desktop windows (T6)

`list` command output (abridged), one Dolphin minimized, Kate moved to
Desktop 2:

```
{"desktop":"15d4e298-...","area":{"x":0,"y":0,"width":1920,"height":1080},"windows":[
 {"desktopFileName":"org.kde.dolphin","minimized":true,"frameGeometry":{"x":960,"y":540,"width":960,"height":540},
  "clientGeometry":{"x":960,"y":568,"width":960,"height":512},"fraction":{"x":0.5,"y":0.5,"width":0.5,"height":0.5}, ...},
 {"desktopFileName":"org.kde.konsole","frameGeometry":{"x":960,"y":0,"width":960,"height":540},"fraction":{...}, ...},
 {"desktopFileName":"org.kde.konsole","frameGeometry":{"x":0,"y":540,"width":700,"height":540},
  "fraction":{"x":0,"y":0.5,"width":0.3645833333333333,"height":0.5}, ...},
 ...]}
```

- `workspace.stackingOrder` gives bottom-to-top order; filter by
  `w.onAllDesktops || w.desktops.indexOf(d) !== -1`. Kate on Desktop 2 was
  correctly left out.
- Minimized windows keep their last `frameGeometry`.
- `frameGeometry` includes the decoration (title bar 28 px here);
  `clientGeometry` does not. Store `frameGeometry` fractions, since placement
  sets `frameGeometry`.
- Other fields available: `internalId` (UUID string), `pid`, `caption`,
  `resourceName`, `minSize`, `output`, `moveable`, `resizeable`.

## 5. Emptiness check and usable area

Ported in `placer.js` (`checkEmpty`, `usableArea`) and `oneshot-query.js`.

```
no panel:                area 0,0 1920x1080
fakepanel (44 px bottom): area 0,0 1920x1036
```

`workspace.clientArea(KWin.PlacementArea, workspace.activeScreen,
workspace.currentDesktop)` subtracts a layer-shell exclusive zone.

The legacy filter `w.normalWindow && (onAllDesktops || on desktop)` counted
the fake panel as a blocker (`count: 5` with four app windows). Window type
flags (`window-types.js`):

```
org.kde.konsole windowType=0 normalWindow=true dock=false skipTaskbar=false layer=2 onAllDesktops=false minimizable=true  moveable=true
fakepanel       windowType=0 normalWindow=true dock=false skipTaskbar=true  layer=3 onAllDesktops=true  minimizable=false moveable=false
```

With `w.normalWindow && w.minimizable` (the same test KWin's bundled
`minimizeall` script uses) the count became 4, and with only the panel on
screen the check reports `empty: true`. Real Plasma panels declare the
Plasma panel role and should be `dock` windows, which is presumably why the
legacy script works on the live session; but any third-party layer-shell
surface (bars, our own radial menu overlay from S2) would make the desktop
look busy without the extra test.

Per-screen virtual desktops: Plasma 6.7 has
`workspace.currentDesktopForScreen(output)` (used by `minimizeall`). With a
single monitor `workspace.currentDesktop` is the same; T2 may prefer the
per-screen call on `workspace.activeScreen` to be safe.

## Recommended design for daemon <-> script

1. On startup vdwd loads one long-lived script (`isScriptLoaded` ->
   `unloadScript` -> `loadScript` -> `run`) and unloads it on exit.
2. **Placements are pulled, not pushed.** vdwd keeps the pending list. The
   script, on `windowAdded` for an app window, calls
   `ClaimWindow(json windowInfo) -> s` (rect JSON or `""`). If a rect comes
   back, it sets `desktops` and `frameGeometry`, waits for
   `frameGeometryChanged` (or about 100 ms), and calls `WindowPlaced(json)`.
   No push channel is needed, and a dead daemon simply means no placement.
3. **Queries use one-shot scripts**: check, usable area and list are each a
   tiny generated script that calls back `Report`-style methods with JSON,
   correlated by a request id baked into the script text. They run in a few
   ms and keep the long-lived script minimal. (Alternative if one-shots turn
   out slow on real hardware: let the long-lived script handle them via the
   doorbell, accepting the persisted shortcut entry.)
4. Do not use `registerShortcut` as a doorbell and do not use script config.

## Unverified

- Real plasmashell panels (tested only a plain layer-shell surface). Check
  on the live session that `normalWindow && minimizable` still counts every
  real app window and no panel / desktop / widget.
- Whether the window is visible for a frame at KWin's default position
  before it jumps (`windowAdded` fires after the first buffer; the new rect
  lands 2 to 10 ms later). Headless, nothing to look at. Needs the user to
  watch it once on the live session. If it is visible, the fix is KWin
  window rules (applied before mapping), which is a much bigger change.
- Apps that restore a maximized or fullscreen state; may need
  `w.setMaximize(false, false)` / `w.fullScreen = false` before setting the
  geometry.
- Apps slower than ~200 ms to map (cold start, Electron, Firefox), and apps
  whose desktop id differs from their Wayland app id (S4).
- `readConfig` for scripts loaded with `loadScript`: which group it reads
  was not worked out (option rejected anyway).
- Multi-monitor (out of scope).

## Recommendations

- **T1 (D-Bus API / names):** vdwd needs a script-facing interface besides
  the public one, e.g. `org.kde.vdw.Script` with `ClaimWindow(s) -> s`,
  `WindowPlaced(s)`, `QueryResult(s requestId, s json)`. JSON strings keep
  the KWin JS side trivial. Install a D-Bus `.service` file so `callDBus`
  can auto-start vdwd.
- **T2 (placement):** implement the pull design above; match on
  `desktopFileName`, fall back to `resourceClass`; confirm on
  `frameGeometryChanged`, do not trust the read-back; set `w.desktops` to
  the target desktop; filter app windows with `normalWindow && minimizable`;
  handle crash-restart by unloading a stale script of the same name; keep a
  pending timeout on the daemon side (callbacks may never come). Emptiness
  check and usable area: copy `oneshot-query.js`.
- **T6 (save current desktop):** use `listWindows()` from `placer.js`
  (one-shot): `stackingOrder`, desktop filter, `normalWindow && minimizable`,
  `frameGeometry` divided by `clientArea(PlacementArea, ...)`, app id from
  `desktopFileName` (skip or warn when empty), include minimized windows.

## Proposed ARCHITECTURE/DECISIONS changes

- ARCHITECTURE, "KWin script": replace "match new windows against pending
  placements" with: "on `windowAdded`, ask vdwd over `callDBus`
  (`ClaimWindow`) whether a placement is pending; vdwd owns the pending list
  and does the matching. Emptiness check, usable area and window listing run
  as one-shot scripts that report back over `callDBus`." Also note the
  `normalWindow && minimizable` filter.
- DECISIONS (new entry): "Daemon to KWin script: script pulls placements
  with `callDBus` on `windowAdded`; queries run as one-shot scripts. No
  shortcut doorbell, no script config. Why: S3, no push channel exists into
  a loaded script, `registerShortcut` persists a visible shortcut entry,
  `readConfig` did not pick up external writes."

## dev-session.sh

No changes. Notes: `script` uses a fixed `sleep` (`VDW_SCRIPT_WAIT`) before
unloading, so a script with async `callDBus` callbacks needs a larger wait;
the spike loaded long-lived scripts directly with `qdbus6` through `run`
instead (`spikes/S3/q.sh load`).
