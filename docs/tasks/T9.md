# T9: Browser profile follow-ups

**Depends on:** T8. Decisions: DECISIONS 36 to 47.

Items that T8 did not do. Each item is small. Plan them one at a time.

## Items

- **Other Chromium browsers:** chromium, google-chrome, brave, vivaldi and
  edge, and their Flatpak versions. Each browser is one more row in the
  browser table (`findBrowser` in `src/lib/browserprofile.cpp`). A Flatpak
  browser keeps `Local State` in a different folder.
- **Firefox profiles:** Firefox uses `-P <name>` and `profiles.ini`, not
  `Local State`. The `Profile` key is generic, so the config format does not
  change. Firefox needs its own backend.
- **Forced open during an earlier open:** a forced open can start while an
  earlier open still waits for windows of the same browser. The two opens
  share the pending list, so the windows of the two opens can go to the wrong
  slots. The launch queue is for one open only.
- **Integration test gap:** no test has a browser slot that waits on an
  expired launch or on a held launch. No test has a hand-over in a chain of
  browser slots. A review of the code found no problem.

## Acceptance

- Each item that you do has a unit test or an integration test, as T8 has.
- A new browser opens in its saved profile, and the KCM shows its profiles.
