# T7: Packaging, autostart, migrate off the bash script

**Depends on:** everything else (done). **Owns:** the whole repo, but only
the files listed below change. Nothing outside the repo is installed,
removed or edited by the implementer: the user installs the package and the
coordinator runs the migration with the user.

User decisions (DECISIONS 22 to 25): PKGBUILD install, XDG autostart plus
D-Bus activation, a starting "3 Konsoles" workspace, retire the bash script.

## Scope

- **Install rules** (CMake): `vdwd` and `vdwctl` to `KDE_INSTALL_BINDIR`, the
  D-Bus service file (exists), the KCM plugin to the standard KCM location
  with its metadata so System Settings lists it (check `kcmutils_add_qml_kcm`
  already installs it; fix if not), and an XDG autostart file
  `io.github.librv.vdw.desktop` installed to `KDE_INSTALL_AUTOSTARTDIR`
  (`Exec=vdwd`, `NoDisplay=true`, `OnlyShowIn=KDE`,
  `X-KDE-autostart-phase=2`). `vdw-menu-demo` and tests stay uninstalled.
  Verify with `DESTDIR=/tmp/vdw-destdir cmake --install build/dev` and list
  what lands where.
- **Starting workspace:** when vdwd starts with the default config path (not
  `--config`) and `~/.config/vdwrc` does not exist, it writes a built-in
  default through the shared config writer: workspace `3-konsoles`, name
  "3 Konsoles", icon `utilities-terminal`, three `org.kde.konsole` slots at
  top-right `0.5,0,0.5,0.5`, bottom-left `0,0.5,0.5,0.5`, bottom-right
  `0.5,0.5,0.5,0.5` (the legacy layout), set as `DefaultWorkspace`. Never
  overwrite an existing file. Unit or integration test: start vdwd with a
  missing config in the nested HOME and check `vdwctl list`.
- **PKGBUILD** in `packaging/arch/PKGBUILD` (package `vdw`): builds from the
  local checkout (no network fetch of this repo), `cmake -B build -G Ninja
  -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_INSTALL_PREFIX=/usr
  -DBUILD_TESTING=OFF`, installs into `$pkgdir`. `depends` lists the runtime
  KF6/Qt6/LayerShellQt/Kirigami packages actually linked or imported from
  QML (check with `ldd` and the QML imports, map to Arch package names with
  `pacman -Qo`); `makedepends` cmake, extra-cmake-modules, ninja. Check with
  `makepkg --printsrcinfo` and, if it works without sudo, `makepkg -f`
  (build only, never `-i`).
- **Retire the bash script:** delete `setup-workspace.sh` from the repo;
  rewrite `README.md` for the new app: what it does (tap, hold menu,
  confirm, per-workspace shortcuts, capture, settings page), build, install
  with `makepkg -si` from `packaging/arch`, first run, uninstall
  (`pacman -R vdw`), and "Migrating from setup-workspace.sh" (remove the
  Meta+Ctrl+D Custom Shortcut in System Settings, delete
  `~/.local/share/applications/net.local.setup-workspace.sh.desktop` and
  `~/.local/bin/setup-workspace.sh`). In `CLAUDE.md`, remove the rule about
  keeping `setup-workspace.sh` working.
- **Live-session checklist:** `docs/LIVE-CHECKS.md` that merges the user
  steps from `docs/spikes/S1.md`, `S2.md` and `T3b.md` into one ordered list
  for the installed app (tap, hold menu, confirm both paths, workspace
  shortcut, capture, settings page, rebinding in System Settings, theme
  switch), each with the expected result.
