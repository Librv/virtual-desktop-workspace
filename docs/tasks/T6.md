# T6: Save current desktop as workspace

**Depends on:** T2, T3b. **Owns:** `src/lib/`, `src/daemon/`,
`autotests/`, and `src/kcm/` only for moving the config writer (no KCM
behavior changes).

Design: `docs/ARCHITECTURE.md` (Config, D-Bus API, KWin script),
`docs/spikes/S3.md` (`listWindows()` in `spikes/S3/placer.js`).

## Design (fixed)

- **Shared writer:** move `src/kcm/configwriter.{h,cpp}` and its test into
  `vdwcore` (`src/lib/`, test in `autotests/`), keeping its API and
  behavior; the KCM uses it from there. The daemon writes `vdwrc` only
  through it.
- **`CaptureCurrentDesktop(name)`:**
  - empty or blank name: reply `"error: a name is required"`;
  - one-shot `list.js` query: windows on the current desktop that are
    `normalWindow && minimizable`, excluding vdwd's own pid (same filter as
    the emptiness check), in stacking order bottom to top, each with
    `frameGeometry` and `desktopFileName`;
  - usable area query as in `OpenWorkspace`; each window's rect becomes
    fractions of the area, clamped to 0..1 (width and height at least one
    pixel's worth);
  - a window is skipped when `desktopFileName` is empty or no `KService`
    resolves it; skipped windows are logged by caption and class;
  - no usable window left: reply `"error: no windows to capture"`;
  - new workspace: id = unique slug from the name (the writer's slug
    function), `Name` = name, `Icon` = icon of the first slot's app,
    `Order` after the last workspace, `Args` empty;
  - write through the writer, reload the config (so the shortcut action
    appears), reply the new id.
- `vdwctl capture <name>` already exists; it prints the id.

## Acceptance

- Unit tests still pass after the writer move (KCM tests included).
- Nested integration test: open a 3-Konsole workspace, capture it as
  "Captured", close the windows, open the captured workspace, and its
  windows land within 2 px of the originals. Capture with an empty name and
  on an empty desktop give the two error replies.
