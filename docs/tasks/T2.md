# T2: Launch and placement engine (daemon core)

**Depends on:** T1. **Owns:** `src/lib/`, `src/daemon/`, `src/vdwctl/`,
`autotests/`. Do not touch `src/gesture/`, `src/menu/`, `src/kcm/` or the
top-level `CMakeLists.txt` (other tasks run in parallel; add any
`find_package` you need in `src/daemon/CMakeLists.txt`).

Design: `docs/ARCHITECTURE.md` sections "vdwd" (Launching), "D-Bus API",
"KWin script", "Matching windows to launches"; DECISIONS 12 and 13.

## Scope

- `src/lib/layout.{h,cpp}`: fractions to pixel rect of the usable area
  (pure, tested; round to whole pixels, slots flush against each other).
- `src/lib/matcher.{h,cpp}`: pure matcher. Input: pending launches (slot id,
  pid, app id, rect, launch time) and observed windows (pid,
  desktopFileName, resourceClass, internalId, time). Rules: pid first, then
  oldest pending with the same `desktopFileName` (`resourceClass` if empty),
  expiry after `PlacementTimeoutMs`. Unit tests cover every case in
  `docs/spikes/S4.md` (out-of-order arrival, unrelated window of the same
  app, shared process, no window at all, expiry).
- `src/daemon/kwin/`: `placer.js` (long-lived) and one-shot query scripts
  (emptiness, usable area), embedded via a Qt resource and written to
  `$XDG_RUNTIME_DIR/vdw/` at startup so `loadScript` gets a file path. Start
  from `spikes/S3/placer.js` and `oneshot-query.js`.
  - App windows are `normalWindow && minimizable`; the emptiness check also
    ignores windows whose pid is vdwd's own (the radial menu later).
  - Placer: on `windowAdded` call `ClaimWindow(json)`; on a rect, set
    `frameGeometry`, wait for `frameGeometryChanged`, call `WindowPlaced`.
- `src/daemon/kwinscripts.{h,cpp}`: load the placer at startup
  (`isScriptLoaded` then `unloadScript` then `loadScript` then `run`),
  run one-shot queries with a request id and resolve them from
  `QueryResult`, with a timeout.
- `src/daemon/launcher.{h,cpp}`: `KIO::ApplicationLauncherJob` with a
  `KService` copy whose `Exec` gets the slot args appended; pid from the
  `result` handler (`docs/spikes/S4.md`, `spikes/S4/s4launch.cpp`).
- `Manager::OpenWorkspace(id, force)`: delayed D-Bus reply. Query emptiness;
  busy and not forced replies `"busy"`; otherwise query the usable area,
  launch every slot, register pending placements, reply `"opened"` once the
  launches are started (do not wait for windows). Errors reply
  `"error: ..."`.
- `ScriptApi::ClaimWindow` asks the matcher; replies a pixel rect JSON
  `{x, y, width, height}` or `""`.
- Kate: launches handed to a running instance open no window. Check whether
  `kate --new` fixes it; report the finding, do not add per-app special
  cases in code.

## Acceptance

- Unit tests for layout and matcher pass in `ctest --preset dev`.
- Integration test in the nested session: with a 3-Konsole test config,
  `vdwctl open` on an empty desktop places 3 Konsoles at their slot rects
  (check with a KWin script listing geometries, within 2 px); a second
  `vdwctl open` replies `busy` and launches nothing; `vdwctl open --force`
  places 3 more.
